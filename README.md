# アルファ受注ナビ

アルファパーチェスの案件管理アプリ。見積依頼・注文のメールを読み取り、種別(見積依頼/注文)・取引先・品目・数量・単価・見積の回答期限・希望納期・納品先を抜き出して案件を自動で登録します。
構成は「大東受注ナビ」と同じです(単一HTML + Vercel のサーバー関数 + Upstash Redis)。

## 作業依頼書(ZIP・PDF)の取込
- 「依頼の取込」に、メール添付の ZIP(パスワード付きも可)か作業依頼書PDFをドロップすると、店舗名・店舗コード・作業場所・店舗電話・作業依頼番号/顧客案件番号・区分・作業名称・作業内容・工期・依頼元の担当を読み取って登録します。
- アルファパーチェスの作業依頼書の書式はそのまま読み取ります(AI不要)。書式が違うPDFや文字の入っていないPDFは、AIで読み取ります(公開ページ版のみ)。
- パスワード付きZIPは、パスワード欄が空ならGmail(claude.ai のコネクタ)で添付メールをファイル名で探し、同じ差出人の直後・直前のメール(と同じ時間帯のパスワード通知メール)の本文から候補を抜き出して、実際にZIPが開けるものを使います(公開ページ版のみ)。
- 同じ作業依頼番号が登録済みのときは、重複として知らせます。
- ブラウザで使うライブラリ: pdf.js 3.11.174(cdnjs)、zip.js 2.7.62(jsDelivr)

## メールの自動取込(Gmail → 5分ごと)
`gas/importOrders.gs`(画面の「依頼の取込」にもコピー用があります)を、依頼メールが届く Gmail の Google Apps Script に貼り付け、`TOKEN` を `INBOUND_TOKEN` と同じ値にして、トリガーで `importOrders` を5分おきに実行します。

- 添付の ZIP・PDF があるメール: 添付と、同じ差出人の**直前・直後のメール**(と同じ時間帯のパスワード通知)の本文を `/api/inbound` に送ります。サーバーがパスワード候補を試して ZIP を開き、作業依頼書PDFを読み取って登録します。PDF は保存され、案件画面から開けます。
- パスワードのメールがまだ届いていないときは 422 を返し、ラベルを付けずに次の回にやり直します。
- 添付のないメールは本文から見積依頼・注文として登録します。パスワード通知だけのメールは単独では登録しません。
- 同じ作業依頼番号・同じメールは二重に登録しません。処理済みのスレッドには「AP取込済」ラベルが付きます。

## 写真と作業完了報告書
- 案件を開くと「写真を追加」(1案件30枚まで)。スマホの写真も自動で縮小(長辺1280px・JPEG)して保存します。作業前・作業中・作業後の区分と説明を付けられます。
- 「報告書を作成」で、案件の情報と写真を並べた「作業完了報告書」を表示します。文章は画面で直接書き換えられ、「印刷 / PDF保存」でPDFにできます。
- `ANTHROPIC_API_KEY` を設定すると「写真から文章を作る(AI)」が使え、写真の説明と作業内容のまとめを自動で入れます(確認して直してから使ってください)。
- 保存先: Vercel版は `api/photo.js` → Redis(`/api/file` で表示)。公開ページ版は assets に保存します。

## できること
- **メールから自動登録** … 「メール取込」にメールを貼り付ける/.eml をドロップすると、読み取ってそのまま登録(「登録前に確認」も選べます)
- **Gmail 自動取込** … Gmail に届いた受注メールを5分ごとに自動で登録(Google Apps Script、下記)
- 受注番号の自動採番(`AP-yymmdd-001`)、同じメールの二重登録防止、受注でないメール(メルマガ等)の自動除外
- 読み取りに不安がある案件には「要確認」、至急の依頼には「至急」が付きます。元メールは案件の中でいつでも見られます
- 受注一覧(状態・担当・要確認・納期での絞り込み、検索、CSV出力)、ホーム(要対応・納期3日以内・超過・今月の受注額)、取引先の集計
- 状態: 依頼受付 → 現地確認・見積作成 → 見積提出済 → 施工予定 → 作業完了 → 完了報告済 → 請求済 → 入金済(/キャンセル)
  - 期限: 見積前は見積提出期限、施工予定は作業予定日、作業完了は報告期限(作業日+2日。作業依頼書の注意事項より)
  - 見積依頼メールは「見積依頼受付」から、注文メールは「受注確定」から始まります
  - 見積の回答前は「回答期限」、受注後は「納期」を期限として追いかけます
- 公開ページ版(`dist-artifact.html`、`python3 build.py` で作成)は claude.ai 上でデータ共有・AI読み取り・Gmail取込が動きます

## Vercel への公開
1. このフォルダを GitHub に置き、Vercel で New Project → インポート
2. Storage → **Upstash Redis** を追加(`KV_REST_API_URL` / `KV_REST_API_TOKEN` が自動で入ります)
3. 環境変数を設定して再デプロイ

| 名前 | 内容 |
|---|---|
| `APP_PASSWORD` | ログイン用の共通パスワード(必須) |
| `ANTHROPIC_API_KEY` | メールのAI読み取り用(推奨。なしでも簡易解析で動きます) |
| `INBOUND_TOKEN` | Gmail 自動取込の合言葉(16文字以上の長いランダム文字列) |
| `SESSION_SECRET` | ランダムな長い文字列(任意・推奨) |
| `ANTHROPIC_MODEL` | 使うモデルを変えるとき(任意。既定は `claude-sonnet-5-5`) |

## Gmail 自動取込の設定
1. 受注メールが届く Gmail アカウントで https://script.google.com/ を開き、新しいプロジェクトを作成
2. アプリの「メール取込」画面にあるコードをコピーして貼り付け、`TOKEN` を `INBOUND_TOKEN` と同じ値に書き換え
3. 左の「トリガー」→「トリガーを追加」→ 関数 `importOrders` / 時間主導型 / **5分ごと**
4. 初回実行時に Gmail へのアクセスを許可

処理したメールには「AP取込済」ラベルが付き、次回は対象外になります。拾う条件は `QUERY` で変えられます
(例: 特定の宛先だけ → `to:order@alpha-purchase.example`)。サーバーが失敗したメールはラベルが付かず、次回やり直します。

## AI 読み取りについて
- メール本文は Anthropic の Claude API に送られて読み取られます。
- 本文中の指示(「これまでの指示を無視して…」など)には従わないよう指示しています。読み取り結果は必ず画面の項目として表示され、不安な点は「要確認」になります。
- AI がエラーや時間切れのときは、ルールによる簡易解析に自動で切り替えて登録します(取りこぼし防止)。

## ローカルで試す
```
node dev/server.js          # http://localhost:3000(パスワード test1234、データはメモリ上)
npm test                    # 解析とAPIのテスト
```
`index.html` をそのままブラウザで開くと「お試しモード」(ブラウザ内保存・簡易解析)で動きます。

## 書類(作業依頼書・作業完了報告書)
アルファパーチェスの案件は「作業依頼書」と「作業完了報告書」の2枚が基本です。メール添付のZIP・PDFや、ホームの「作業依頼書PDFを追加」から読み込むと、
案件番号(作業依頼番号 / 顧客案件番号)で同じ案件にまとめ、案件を開くと2枚を画像のように並べて表示します(クリックで拡大、差し替えも可能)。
作業完了報告書が先に届いたときは仮の案件を作り、作業依頼書が届くと内容を確定します。
